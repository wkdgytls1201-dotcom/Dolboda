# 돌보다 공공데이터 기반 안심지수 기술서

> ⚠️ **이 문서는 돌보다의 핵심 자산 명세입니다.**
> `lib/dolbodaScore.ts`를 수정할 때는 반드시 이 문서를 함께 갱신하세요.
> 가중치·매핑·보정 로직의 변경은 전 시설의 점수를 바꾸므로, 변경 이력 표에 기록을 남깁니다.

최종 갱신: 2026-07-31 · 구현 파일: [lib/dolbodaScore.ts](../lib/dolbodaScore.ts) · 표시 컴포넌트: [components/DolbodaScoreCard.tsx](../components/DolbodaScoreCard.tsx)

## 1. 목적과 설계 철학

보호자가 시설을 고를 때의 실제 의사결정 순서를 점수 구조에 그대로 반영한다.

1. **1순위 불안: "학대당하지 않을까"** → 안전·신뢰에 최대 가중치 **27%**
2. **2순위 불안: "갑자기 아프면 대응이 될까"** → 의료·간호 대응을 독립 영역으로 신설, **23%**
3. **환경(청결·냄새)은 방문하면 직접 확인 가능** → 플랫폼 정보가치가 낮아 **10%**로 하향

3대 원칙:
- **없는 데이터는 지어내지 않는다.** 미확보 신호는 제외하고, 그 사실을 화면에 그대로 공개한다.
- **부족한 데이터로 단정하지 않는다.** 확보 가중치 50% 미만이면 점수 산출을 보류한다.
- **만점 인플레를 막는다.** 미확보 가중치만큼 전국 평균(65점)으로 수렴시켜, 데이터가 적은 시설이 데이터가 많은 시설보다 유리해지지 않게 한다.

## 2. 영역과 가중치 (합계 100)

| 영역 키 | 이름 | 가중치 | 근거 |
|---|---|---|---|
| safety | 안전·신뢰 | 27% | 학대·부당청구 불안이 보호자 1순위 |
| medical | 의료·간호 대응 | 23% | 응급 대응력이 2순위 |
| care | 돌봄·운영 전문성 | 20% | 일상 돌봄의 질 |
| environment | 생활·환경 | 10% | 방문 시 직접 확인 가능한 영역 |
| transparency | 정보 투명성 | 10% | 비용·정보 공개 성실도 |
| availability | 이용 가능성 | 10% | 지금 이용할 수 있는가 |

## 3. 신호 매핑

각 영역 점수 = 영역 내 신호들의 **가중 평균** (신호별 weight, 기본 1).
`score: null`인 신호는 계산에서 제외된다.

※ **요양보호사 배치의 만점 경계선 2.1은 법정 기준이 아니다.** 요양원 법정 배치기준은
입소자 **2.3명당 1명**(노인복지법 시행규칙, 2022년 개정 전 2.5명)이고, 우리는 그보다 엄격한
2.1을 만점으로 둔다 — 법정 최저선을 만점으로 잡으면 기준만 겨우 지킨 시설과 여유 있게 배치한
시설이 구분되지 않기 때문이다. 실제 분포의 p25도 2.25로 이 근처다
([work-index-spec.md](work-index-spec.md) §3의 분포와 같은 데이터).
2026-08-01 이전에는 코드 주석과 이 표가 2.1을 "법정 기준"이라고 잘못 적고 있었다.

※ 방문요양(HOME_CARE)은 정원 개념이 없어 생활·환경/이용 가능성 신호가 대부분 null →
등급까지 없으면 대개 커버리지 50% 미만으로 **산출 보류**가 된다 (의도된 동작).

## 4. 총점 계산

```
영역점수  = Σ(신호점수 × 신호weight) / Σ(신호weight)      -- null 신호 제외
확보가중치 = Σ(점수가 있는 영역의 가중치)                    -- coverage로 표시
if 확보가중치 < 50: 총점 = null (산출 보류)
원점수    = Σ(영역점수 × 영역가중치) / 확보가중치
총점      = (원점수 × 확보가중치 + 65 × (100 - 확보가중치)) / 100   -- 평균 수렴 보정
```

### ★ 등급 라벨은 **유형별**이다 (2026-08-06 개편)

| 유형 | 매우 우수(p90) | 우수(p75) | 보통(p25) |
|---|---|---|---|
| 요양원 | 91 | 87 | 78 |
| 요양병원 | 88 | 84 | 75 |
| 주야간보호 | 87 | 82 | 71 |
| 방문요양 | 72 | 68 | 54 |

(`SCORE_LEVEL_BY_TYPE`·`scoreThresholdsOf()`, `lib/dolbodaScore.ts`. 유형을 모르면
`SCORE_LEVEL_THRESHOLDS`(86/79/62 = 전체 분포 기준)로 떨어진다.)

**왜 나눴나** — 하나의 전체 분포로 문턱을 잡았더니 유형에 따라 라벨이 불공평했다.
2026-08-06 전수 대조(18,136곳):

| 유형 | "우수" 이상 | "확인 필요" | 중앙값 |
|---|---|---|---|
| 요양원 | 72.4% | 1.2% | 84 |
| 요양병원 | 58.9% | 1.0% | 80 |
| 주야간보호 | 38.9% | 3.1% | 80 |
| **방문요양** | **0.5%** | **47.3%** | **67** |

방문요양은 15,677곳으로 **전체의 54%**인데 "우수"가 0.5%(78곳)뿐이었고 절반 가까이가
"확인 필요"였다. 원인은 시설 품질이 아니라 계산 구조다 — `nhisAreas()`가 네 유형을 함께
처리하는데 **방문요양에는 정원·침실 구성·프로그램실·격리실이 존재하지 않는다.** 그 미확보
가중치가 `PRIOR_SCORE`(65)로 채워져 방문요양 중앙값이 67에 눌렸다(점수가 아니라 기본값이
표시되던 셈이다). 부작용도 실측됐다: "방문요양 + 안심지수 우수" 조합이 사실상 죽은 조합이었다.

**개편 후**(같은 전수 대조): 우수 이상 25.7~29.9% · 확인 필요 7.2~24.9%로 유형 간 균형이 맞았다
(방문요양 확인 필요 47.3% → **7.2%**).

**가중치·신호 매핑·계산식은 전혀 바꾸지 않았다** — 점수는 그대로고 부르는 이름만 바뀐다.
대신 라벨의 뜻이 "전국 전체에서"가 아니라 "같은 유형 안에서"로 바뀌었으므로,
시설 상세는 라벨 아래에 **"전국 ○○○ 중에서"**를 함께 표시한다(`DolbodaScoreCard`).
기준을 밝히지 않으면 뜻이 바뀐 것을 숨기는 셈이 된다.

참고 — 개편 전 기준의 근거(2026-08-02 실측, 28,118곳):
**p10=54 · p25=62 · p50=70 · p75=79 · p90=86 · p99=93**.

이전 기준(85/70/55)은 **70점 이상이 전체의 50.1%**여서 "우수"가 사실상 중앙값이었다.
그래서 국가 평가등급 3등급 시설의 절반(50.8%)이 "우수"로 표시됐고, 보호자에겐
"국가는 3등급인데 돌보다는 우수?"로 읽혔다. 점수 산식은 그대로 두고 라벨만 조정했다.

참고 — 등급별 안심지수 평균(같은 실측): 1등급 80.4 / 2등급 76.5 / 3등급 71.9 /
4등급 64.4 / 5등급 62.5 / 등급없음 62.7. 등급과 단조 감소 관계라 지수 자체는 정상 작동한다.

**지표 건강성 전수 검증**(2026-08-06, `scripts/audit-score-vs-grade.mjs` — 등급이 있는 18,136곳):
- 스피어만 순위상관(등급 vs 지수) **−0.530**. 방향이 맞고(등급이 좋을수록 지수도 높다),
  등급의 복사본도 아니다 — 지수가 등급이 못 보는 것을 함께 본다는 뜻.
- 극단 불일치 거의 없음: **1등급인데 하위 20%는 1곳, 5등급인데 상위 20%는 0곳.**
- 이 스크립트는 dev 서버의 `/api/facilities?ids=...&view=card`로 점수를 받는다
  (점수 함수가 TS라 순수 node에서 못 부른다 — **화면이 쓰는 값 그대로** 대조하는 게 목적).
  점수 로직을 손대면 이 스크립트를 다시 돌려 상관·이상치가 무너지지 않았는지 볼 것.

같은 문턱을 쓰는 곳: 목록 카드 배지 색(`FacilityCard`), 시설찾기 "안심지수 우수만" 필터,
홈 "이 지역 안심지수 TOP" 진입선, 시설 상세 라벨(`DolbodaScoreCard`).
값을 바꾸면 이 네 곳이 함께 움직인다 — **네 곳 모두 `scoreThresholdsOf(facilityType)`을 쓴다.**
전체 기준 상수를 직접 import 하지 말 것(유형별 문턱을 우회하게 된다).

### 보조 데이터 흐름 — `/api/facilities/score-context`
시설 상세 페이지가 시설당 1회 `/api/facilities/score-context?id=...`를 호출해 세 가지를 함께 받는다:
1. **인근 요양병원 접근성** — 비병원 시설의 좌표 기준 최근접 요양병원 거리(km). `calcDolbodaScore(f, { nearestHospitalKm })`로 전달
2. **같은 시군구·같은 유형 안심지수 평균** — 서버가 해당 시군구의 같은 유형 시설(최대 800곳, mock 제외)을 전부 조회해 **상세페이지와 동일한 `calcDolbodaScore` 산식**으로 계산한 평균. 표본이 3곳 미만이면 표시하지 않음
3. 지역명·표본 수

응답 전에는 인근 병원 신호가 null이라 점수가 잠깐 낮게 보였다가 도착 후 갱신된다.
지역 평균 비교는 `DolbodaScoreCard`의 히어로 영역에 "OO구 같은 유형 N곳 평균 X점 · 이 시설 +Y점" 배지로 표시한다.

**비교는 반드시 같은 산식이어야 한다.** 배지가 `score.total - regionAverage`를 그대로 빼서
보여주기 때문이다. 2026-08-01 이전에는 표시 중인 시설만 `nearestHospitalKm`(의료·간호 영역,
weight 2)을 갖고 평균 쪽은 그 신호 없이 계산돼, 서로 다른 산식의 두 숫자를 빼고 있었다.
지금은 좌표가 있는 요양병원 목록(약 1,500곳)을 하루 캐시로 한 번 읽고, 이웃 시설도 각자의
최근접 병원 거리를 넣어 계산한다. 이 조회들은 (유형, 시군구)별로 하루 캐시된다.
